## 1. 프로젝트 개요

Megabonky는 Unreal Engine 5 기반의 멀티플레이어 액션 게임으로, Gameplay Ability System(GAS)을
활용한 능력 기반 전투 시스템을 갖춘 프로젝트입니다. 플레이어는 다양한 무기를 장착하고 적과 전투하며,
레벨업을 통해 캐릭터와 무기를 강화할 수 있습니다.

주요 특징:
- Gameplay Ability System(GAS) 기반 전투 시스템
- 네트워크 멀티플레이어 지원
- 무기 기반 능력(Ability) 시스템
- 속성(Attribute) 기반 캐릭터 성장
- 데이터 테이블 기반 무기 및 업그레이드 관리

## 2. 클래스 계층 구조 (Class Hierarchy)
================================================================================

### 2.1 Core 게임 프레임워크

AGameModeBase
└── AMgbGameModeBase                    - 게임 모드 (적 생성 여부 관리)

AGameStateBase
└── AMgbGameStateBase                   - 게임 상태 (시간, XP, 레벨, 적 생성 관리)

APlayerState
└── AMgbPlayerState                     - 플레이어 상태 (기본 구조만 존재)

APlayerController
└── AMgbPlayerController                - 플레이어 컨트롤러 (입력, UI, 무기 업그레이드)


### 2.2 캐릭터 계층 구조

ACharacter + IAbilitySystemInterface
└── AMgbCharacter                       - 기본 캐릭터 (ASC 소유, 데미지 처리)
    ├── AMgbPlayerCharacter             - 플레이어 캐릭터 (이동, 카메라, 무기 장착)
    └── AMgbEnemyCharacter              - 적 캐릭터 (AI 이동, 타겟 추적, 벽 등반)


### 2.3 무기 시스템

AActor + IAbilitySystemInterface
└── AMgbWeapon                          - 무기 베이스 (ASC 소유, 능력 보유)


### 2.4 Gameplay Ability 계층 구조

UGameplayAbility
└── UMgbGameplayAbility                 - 기본 어빌리티 (플레이어 ASC 접근)
    ├── UMgbGameplayAbility_Lightning   - 번개 공격
    └── UMgbGameplayAbility_Projectile  - 발사체 기반 공격
        ├── UMgbGameplayAbility_Dagger      - 단검 투척
        └── UMgbGameplayAbility_Bananarang  - 부메랑 투척


### 2.5 Actor 시스템

AActor
├── AMgbEffectActor                     - GameplayEffect 적용 액터
├── AMgbItemActor                       - 아이템 액터 (픽업 가능)
├── ADamageTextActor                    - 데미지 텍스트 표시 액터
└── AMgbProjectileActor                 - 발사체 액터 (충돌, 바운스 처리)
    └── AProjectile_Bananarang          - 부메랑 발사체 (플레이어 복귀)


### 2.6 UI 계층 구조

UUserWidget
└── UMgbWidget                          - 기본 위젯 (Show/Hide)
    ├── UInGame                         - 인게임 UI (HP, XP, 아이템 선택)
    ├── UItemSelectWindow               - 아이템 선택 창
    ├── UItemSelectButton               - 아이템 선택 버튼
    └── UDamageText                     - 데미지 텍스트
    └── UTitle                          - 타이틀 화면


### 2.7 Ability System Component

UAbilitySystemComponent
└── UMgbAbilitySystemComponent          - 커스텀 ASC (ActorInfo 초기화)


### 2.8 Attribute Set 계층 구조

UAttributeSet
├── UPlayerAttributeSet                 - 플레이어 속성 (체력, 공격력, 크리티컬 등)
├── UEnemyAttributeSet                  - 적 속성 (체력, 이동속도, 데미지)
└── UWeaponAttributeSet                 - 무기 속성 (데미지, 발사체 수, 크리티컬 등)


### 2.9 기타 시스템

UGameplayEffectExecutionCalculation
└── UMgbEffectExecutionCalculation      - 데미지 계산 (크리티컬, 속성 적용)

UGameInstanceSubsystem
└── UMgbSubsystem                       - 게임 인스턴스 서브시스템 (HTTP 통신)

## 4. 설계 패턴 및 아키텍처
================================================================================

### 4.1 Gameplay Ability System (GAS) 패턴

사용 위치:
  - AMgbCharacter, AMgbWeapon

구현 방식:
  - 캐릭터와 무기가 각각 독립적인 AbilitySystemComponent 보유
  - IAbilitySystemInterface 구현으로 GAS 통합
  - AttributeSet을 통한 속성 관리 (PlayerAttributeSet, EnemyAttributeSet, WeaponAttributeSet)
  - GameplayEffect를 통한 속성 변경 및 데미지 적용
  - ExecutionCalculation을 통한 복잡한 데미지 계산

목적:
  - 능력 기반 게임플레이 시스템 구축
  - 네트워크 리플리케이션 자동 처리
  - 모듈화된 능력 및 효과 관리


### 4.2 다중 ASC 패턴 (Multiple Ability System Components)

사용 위치:
  - AMgbPlayerCharacter (캐릭터 ASC)
  - AMgbWeapon (무기별 ASC)

구현 방식:
  - 플레이어 캐릭터가 자체 ASC를 보유하여 기본 속성 관리
  - 각 무기가 독립적인 ASC를 보유하여 무기별 능력 및 속성 관리
  - 데미지 계산 시 무기와 플레이어 속성을 모두 참조 (ExecutionCalculation)

목적:
  - 무기별 독립적인 능력 관리
  - 다중 무기 시스템 지원
  - 무기 교체 시 능력 동적 변경


### 4.3 네트워크 리플리케이션 패턴

사용 위치:
  - 모든 Core 클래스 (GameState, PlayerController, Character)
  - AttributeSet (ReplicatedUsing 패턴)

구현 방식:
  - Server RPC: 클라이언트 → 서버 (ServerAddXP, ServerApplyWeaponUpgradeEffect)
  - Client RPC: 서버 → 특정 클라이언트 (ClientSpawnDamageTextActor)
  - Multicast RPC: 서버 → 모든 클라이언트 (MulticastUpdateUI_XP, MulticastSetPauseGame)
  - Property Replication: Replicated 속성 (GameStartTime, CurrentLevel, Gold 등)
  - ReplicatedUsing: 속성 변경 시 콜백 함수 호출 (OnRep_XXX)

목적:
  - 멀티플레이어 동기화
  - 서버 권한 보장 (Authority 체크)
  - 클라이언트별 시각 효과 처리


### 4.4 Timer 기반 주기 실행 패턴

사용 위치:
  - AMgbGameStateBase (적 생성 타이머)
  - AMgbPlayerCharacter (무기 능력 활성화 타이머)
  - UMgbGameplayAbility_Projectile (연속 발사 타이머)
  - AProjectile_Bananarang (복귀 타이머)

구현 방식:
  - FTimerHandle 사용
  - GetWorld()->GetTimerManager() 활용
  - 주기적 함수 호출 또는 일회성 딜레이

목적:
  - 게임 로직 스케줄링
  - 주기적 이벤트 처리 (적 생성, 공격 쿨다운)


### 4.5 델리게이트 (Delegate) 패턴

사용 위치:
  - AMgbGameStateBase::OnTimeChanged
  - AMgbItemActor::OnAction

구현 방식:
  - DECLARE_DYNAMIC_MULTICAST_DELEGATE 매크로 사용
  - BlueprintAssignable로 Blueprint 바인딩 지원
  - Broadcast()로 이벤트 발생

목적:
  - 느슨한 결합 (Loose Coupling)
  - UI와 로직 분리
  - Blueprint 통합


### 4.6 데이터 테이블 패턴

사용 위치:
  - AMgbGameStateBase (DT_Weapon, DT_WeaponUpgradeBonus)
  - AMgbPlayerController (DT_Weapons)

구현 방식:
  - FTableRowBase 상속 구조체 정의 (FMgbWeaponInfo, FMgbWeaponUpgradeBonus)
  - UDataTable 참조
  - 런타임에 데이터 테이블 조회

목적:
  - 데이터와 코드 분리
  - 디자이너가 수정 가능한 게임 밸런스
  - 무기 및 업그레이드 정보 중앙 관리


### 4.7 Component 기반 구성 패턴

사용 위치:
  - 모든 Character 및 Actor 클래스

구현 방식:
  - AMgbPlayerCharacter: SpringArmComponent, CameraComponent, SphereComponent
  - AMgbProjectileActor: SphereComponent, ProjectileMovementComponent
  - ADamageTextActor: WidgetComponent

목적:
  - 기능 모듈화
  - 재사용성 향상
  - Unreal의 Component 시스템 활용


### 4.8 Enhanced Input System 패턴

  - 데미지 텍스트 생성 (ClientSpawnDamageTextActor)
  - 입력 처리 (Move, Look, Jump)
  - 로컬 UI 업데이트

[Property Replication]
  - GameState: GameStartTime, CurrentLevel, Gold, TotalKill
  - PlayerCharacter: Weapons, Tomes
  - EnemyCharacter: TargetActor, bSpawnFinished
  - AttributeSets: 모든 속성 (ReplicatedUsing)

## 7. 주요 설계 결정 및 특징
================================================================================

### 7.1 이중 ASC 아키텍처
  - 플레이어와 무기가 각각 ASC를 보유
  - 장점: 무기별 독립적인 능력 관리, 다중 무기 시스템 유연성
  - 단점: ASC 관리 복잡도 증가, 메모리 사용량 증가

### 7.2 광범위한 Attribute 시스템
  - PlayerAttributeSet: 35개의 속성
  - 거의 모든 게임 요소가 Attribute로 관리됨
  - 장점: 통합된 시스템, GameplayEffect로 모든 것 조작 가능
  - 단점: 초기 설정 복잡, 성능 고려 필요

### 7.3 네트워크 중심 설계
  - 모든 중요 로직이 Server Authority
  - RPC 적극 활용 (Server, Client, Multicast)
  - Replicated 속성 광범위 사용
  - 목적: 멀티플레이어 치팅 방지, 동기화 보장

### 7.4 데이터 테이블 기반 밸런싱
  - 무기 정보, 업그레이드 정보 모두 DataTable
  - 코드 수정 없이 밸런스 조정 가능
  - 디자이너 친화적

### 7.5 Enhanced Input System 채택
  - UE5의 최신 입력 시스템
  - 키 리매핑, 입력 컨텍스트 전환 지원

### 7.6 Blueprint 통합
  - Blueprint Implementable Event 다수 활용
  - C++로 기본 로직, Blueprint로 시각/사운드 효과
  - 예: HandleHitEffect, DeathFadeOut, SetItemUpgradeSlot

### 7.7 Timer 기반 게임 루프
  - Tick 최소화
  - Timer를 통한 주기적 이벤트 처리
  - 성능 최적화 고려

## 12. 결론
================================================================================

Megabonky 프로젝트는 Unreal Engine의 Gameplay Ability System을 중심으로 설계된
멀티플레이어 액션 게임입니다. 주요 특징은 다음과 같습니다:

1. **이중 ASC 아키텍처**: 플레이어와 무기가 각각 ASC를 보유하여 유연한 능력 시스템 구현

2. **광범위한 Attribute 시스템**: 35개 이상의 속성으로 세밀한 게임 밸런스 조정 가능

3. **네트워크 중심 설계**: Server Authority 기반으로 치팅 방지 및 동기화 보장

4. **데이터 주도 설계**: DataTable을 통한 무기 및 업그레이드 관리

5. **모듈화된 구조**: Component 기반, Ability 시스템, AttributeSet 분리 등

6. **확장 가능한 아키텍처**: 새로운 무기, 능력, 적 타입 추가 용이

프로젝트의 핵심은 GAS를 활용한 능력 기반 전투 시스템과 무기별 독립적인 ASC를
통한 유연한 무기 시스템입니다. 네트워크 멀티플레이어를 고려한 설계로
확장성과 안정성을 동시에 확보하고 있습니다.

향후 확장 방향으로는 보스 몬스터, 추가 무기 타입, 고급 AI 시스템,
세이브/로드 기능 등이 있으며, 현재 구조에서 큰 변경 없이 확장 가능합니다.
